### 1.1 Границы решения

**Входит в Решение:**

- надстройка над детекторами RoadAR: нормализация, объединение повторов, связывание с точками доступа;
- журнал проездов, визиты, профиль ТС;
- списки контроля, правила доступа, гостевые пропуска;
- оповещения и обработка срабатываний;
- парковки и учёт ТС на территории;
- поиск, инструменты расследований, дела и доказательные пакеты;
- дашборды, отчёты, контроль качества каналов;
- нарушения на территории объекта (скорость и др.) — **расширение**, раздел 6.13;
- клиентские модули (ячейки раскладки, экраны) для клиента Интеллект X и REST/Webhook/MQTT API.

**Не входит в Решение:**

- разработка и обучение нейросетевых моделей распознавания (зона ответственности RoadAR);
- поставка камер, вычислителей, шлагбаумов, табло;
- фиксация нарушений ПДД на дорогах общего пользования с юридической значимостью (требует сертификации СИ и не является целью Решения);
- доработка ядра Интеллект X, кроме согласованных точек расширения.

## 3. Назначение и цели создания

### 3.1 Назначение

Решение предназначено для автоматического распознавания ГРЗ и атрибутов ТС на видеоканалах Интеллект X и построения на этой основе прикладных функций: контроля доступа ТС на КПП, учёта ТС на территории и парковках, оповещения о ТС из списков розыска, поиска и расследований, аналитики и контроля качества распознавания.

### 3.2 Цели

| № | Цель | Измеримый показатель |
|---|---|---|
| Ц1 | Автоматизировать пропуск ТС на КПП | ≥ [90] % проездов по спискам обрабатываются без участия оператора |
| Ц2 | Сократить время реакции на ТС из «чёрных» списков и розыска | Оповещение ≤ [2] с от события детектора; эскалация через [60] с без реакции |
| Ц3 | Обеспечить расследования доказательной базой | Поиск по частичному ГРЗ за период 30 сут — ≤ [3] с; формирование доказательного пакета в один шаг |
| Ц4 | Контролировать качество распознавания | Автоматическое обнаружение деградации канала > [15] % за [30] мин |
| Ц5 | Дать руководству аналитику территории | Дашборд в реальном времени, отчёты по расписанию |

### 5.2 Компоненты

| Компонент | Назначение | Размещение |
|---|---|---|
| **LPR Core Service** | Приём событий детекторов, нормализация ГРЗ, объединение распознаваний в проезды, визиты, матчинг со списками, правила доступа, управление шлагбаумом через макросы/выходы Интеллект X | Серверный модуль Интеллект X; экземпляр на каждом сервере КПП |
| **LPR Storage** | Журнал проездов, профили ТС, списки, срабатывания, дела, аудит, метрики качества. СУБД — PostgreSQL (**уточнить** использование БД Интеллект X или отдельного экземпляра) | Центральный сервер; локальная реплика разрешающих списков и буфер проездов на сервере КПП |
| **Media Store** | Изображения ГРЗ и обзорные кадры; видео — ссылкой на архив Интеллект X | Файловое/объектное хранилище рядом с LPR Storage |
| **Alert Service** | Формирование оповещений, маршрутизация получателям, дедупликация, эскалация, каналы доставки | Центральный сервер |
| **Search & Analytics Service** | Поиск по журналу (маски, нечёткий), инструменты расследований, отчёты, дашборды, сохранённые поиски | Центральный сервер |
| **Integration Gateway** | REST API, Webhook, MQTT, импорт CSV/XLSX, синхронизация с СКУД/1С/ERP, табло | Центральный сервер (DMZ — опционально) |
| **LPR Client Modules** | Экраны и ячейки раскладки клиента Интеллект X (раздел 9) | Клиент Интеллект X; веб-форма гостевой заявки — отдельное веб-приложение (**уточнить**) |

### 5.3 Принципы

- **A1.** Решение не модифицирует детекторы RoadAR и использует их штатные события и настройки DetectorPack.
- **A2.** Видео не дублируется: проезд хранит ссылку на архив Интеллект X (канал + метка времени, окно [−10; +20] с).
- **A3.** Сервер КПП автономен: локально выполняет матчинг по последней копии разрешающих списков и правила доступа; буферизует проезды (6.9 ФТ).
- **A4.** Внешнее взаимодействие — только через Integration Gateway с аутентификацией и журналированием.
- **A5.** Все пользовательские действия, меняющие данные или выгружающие их, фиксируются в журнале аудита.
- **A6.** Справочники, пороги и параметры в `[ ]` хранятся в конфигурации и меняются без перезапуска сервиса.

### 5.4 Поток обработки события (конвейер)

1. Детектор RoadAR публикует распознавание: ГРЗ, страна, тип знака, уверенность, bbox, трек, атрибуты ТС, кадр.
2. **Фильтрация** по минимальному качеству ГРЗ/ТС канала (LPR-SRC-05).
3. **Нормализация** ГРЗ (LPR-REC-08), проверка шаблона страны и типа знака.
4. **Объединение** с открытым проездом этого ГРЗ на канале в интервале объединения; выбор лучшего кадра по уверенности.
5. **Определение направления** и роли (въезд/выезд/транзит).
6. **Матчинг со списками**: точный → шаблонный → нечёткий; проверка срока, расписания, точек; сверка марки/модели (подмена ГРЗ).
7. **Правила доступа** → решение (пропустить / отказать / оператор) → макрос шлагбаума.
8. **Оповещения** по совпадениям; дедупликация.
9. **Запись** проезда, обновление визита, профиля ТС, счётчиков парковки, метрик качества.
10. **Публикация** события во внешние каналы (webhook, MQTT).

Шаги 2–8 выполняются в памяти; бюджет времени от события детектора до оповещения — ≤ [2] с (95-й перцентиль), до команды на шлагбаум — ≤ [1] с.

**Алгоритм матчинга (для LPR-LST-05):**

1. Индекс точных значений: хеш-таблица по нормализованному ГРЗ+стране → O(1).
2. Шаблонные записи: компилируются в автомат; проверяются только при отсутствии точного совпадения в том же списке.
3. Нечёткое совпадение: расстояние Левенштейна ≤ [1] с весом 0 для пар из таблицы похожих символов; выполняется для списков с включённым флагом `fuzzy` (по умолчанию — розыск и чёрный).
4. Для каждого совпадения проверяются срок, расписание, точки; итог — все совпадения, отсортированные по приоритету списка.
5. Бюджет: ≤ [50] мс на проезд при суммарно 1 000 000 записей во всех списках.

## 7. Модель данных

Основные сущности (логическая модель; физическая схема — на этапе проектирования).

```
Site (объект) 1─* CapturePoint (точка фиксации) 1─* Channel (канал)
CapturePoint 0─1 AccessPoint (шлагбаум/ворота)       Channel *─* OverviewCamera
Channel 1─* Recognition ─*→1 Passage (проезд) *─0..1 Visit (визит)
Passage *─1 VehicleProfile (профиль ТС)              Passage 1─* ListMatch ─→ ListEntry
WatchList 1─* ListEntry                               ListMatch 0─1 Alert 1─* AlertAction
AccessRule (точка × список × расписание × направление → решение)
GuestPass ─→ ListEntry (гостевой список)              ParkingZone 1─* OccupancySnapshot
Case 1─* CaseItem (поиск | ТС | проезд | видео)       Case 1─* EvidencePackage
SavedSearch                                           ChannelQualityMetric, Baseline
Violation (расширение)                                AuditLog
```

## 12. Информационная безопасность и защита данных

- **SEC-01.** ГРЗ, связанные с ФИО, телефоном, организацией (пользовательские поля списков), — ПДн; обработка по 152-ФЗ, ИСПДн — уровень защищённости определяется заказчиком.
- **SEC-02.** Аутентификация и авторизация — средствами Интеллект X; доступ к API — по токенам с ограниченным сроком и областью действия.
- **SEC-03.** Шифрование каналов: TLS 1.2+ для API, webhook, MQTT, репликации КПП.
- **SEC-04.** Журнал аудита: вход, просмотр карточек со скрытыми срабатываниями, изменения списков и правил, ручные открытия, исправления ГРЗ, запросы расследований с целью, выгрузки. Журнал неизменяем для пользователей (append-only), срок хранения [3] года.
- **SEC-05.** Скрытые списки розыска: данные не передаются на клиент КПП и в его кэш; локальная копия на сервере КПП содержит только разрешающие списки и правила.
- **SEC-06.** Доказательные пакеты: SHA-256 по файлам, водяной знак, запись в аудит; возможна подпись пакета ключом сервера — **уточнить**.
- **SEC-07.** Маскирование ГРЗ в выгрузках для ролей без права на ПДн — этап C.
- **SEC-08.** Автоматическое удаление данных по срокам хранения (LPR-LOG-05) с отчётом.

## 15. Порядок контроля и приёмки

### 15.1 Виды испытаний

1. **Автономные** — модульные и интеграционные тесты сервисов (покрытие бизнес-логики ≥ [80] %).
2. **Комплексные на стенде** — прогон эталонного набора видео (день/ночь, РФ и иностранные ГРЗ, без ГРЗ, двухстрочные) в ретроспективном режиме; нагрузочные — генератор событий до NFR-P-02.
3. **Приёмочные у заказчика** — по программе и методике испытаний (ПМИ) на реальных точках, не менее [14] сут опытной эксплуатации.

### 15.2 Критерии приёмки (выборка)

| Проверка | Метод | Критерий |
|---|---|---|
| Задержка оповещения | Метки времени события детектора и отображения в клиенте, 1000 событий | p95 ≤ [2] с |
| Нормализация ГРЗ | Поиск «A123BC77» латиницей находит «А123ВС77» кириллицей | 100 % пар таблицы 2.8 |
| Нечёткое совпадение | Запись «О777ОО77», проезд «0777ОО77» | Срабатывание с типом «нечёткое» |
| Скрытое оповещение | Проезд ГРЗ из розыска на КПП | На КПП нет признака; у получателя — срабатывание |
| Эскалация | Без реакции 60 с | Передано следующему получателю, отражено в журнале |
| Автономность КПП | Отключение связи на 2 ч, 200 проездов | Пропуск по спискам работает; после восстановления 200 проездов в центре, без дублей |
| Ручное открытие | Открытие без ГРЗ | Невозможно без причины; запись в журнале проездов и аудите |
| Деградация канала | Перекрытие объектива на 40 мин | Уведомление администратору ≤ 30 мин + интервал агрегации |
| Доказательный пакет | Экспорт дела | Манифест SHA-256 совпадает, водяной знак, запись в аудит |
