# LPR — памятка для Claude Code

Этап проектирования вертикального решения LicensePlateRecognition для ПК Интеллект X: распознавание ГРЗ на детекторах RoadAR и прикладная аналитика (КПП, парковки, списки контроля, расследования, нарушения). Production-кода нет. Обзор — [README.md](README.md).

## Источник истины

- **ТЗ** — [ТЗ_LicensePlateRecognition_Интеллект_X.md](Specification/ТЗ_LicensePlateRecognition_Интеллект_X.md), один действующий файл, версия и статус — в шапке (сейчас 0.1, на согласовании), журнал изменений — [CHANGELOG.md](Specification/CHANGELOG.md). Требования — с идентификаторами `LPR-<модуль>-NN` (модули M1–M13, §6), нефункциональные — `NFR-*`, принципы интерфейса — `UI-NN`; приоритет M / S / C. Значения в `[ ]` — параметры по умолчанию на согласовании, «уточнить» — открытый вопрос из §17.
- **ФТ** — `Specification/ФТ_распознавание_ГРЗ_RoadAR_Интеллект_X.docx`, исходные требования, не правится. Связь ФТ → ТЗ — приложение А ТЗ и пометки `← ФТ x.y`. Пункт ФТ без требования в ТЗ — находка `REQ`; требование с пометкой «расширение» (M13) сознательно вне ФТ.
- **Прототип** — [prototypes/index.html](prototypes/index.html): один самодостаточный файл (~680 КБ), экраны Э1–Э10 из §9.2 ТЗ. Расходится с ТЗ — верно ТЗ. Исходники — `prototypes/src/`: `app.js` (экраны, демо-данные, логика), `app.css`, `body.html`, `selftest.js` (самопроверка); сторонние файлы — `prototypes/vendor/` (токены, компоненты и шрифт ONE PSIM, иконки Octicons — не править, обновлять целиком).
- Оформление — ONE PSIM Prototype Kit (`../ONE.PSIM.PrototypeKit`), светлая и тёмная темы (`data-theme` на `<html>`).
- Ревью и планы — `reviews/<дата>/`, порядок и нумерация — [reviews/README.md](reviews/README.md).

## Проверки

Быстрые — после любой правки (на Windows `python`, на Linux `python3`):
`python tools/kit/check_links.py`, `python tools/kit/check_ids.py`, `python tools/check_trace.py`, `python tools/build_prototype.py --check`.

| Поменял | Дополнительно |
|---|---|
| ТЗ | `check_ids.py --unused` — новые требования, на которые нет ссылок из экранов §9.2, этапов §14 или приложения А; запись в `Specification/CHANGELOG.md` |
| `prototypes/src/*.js` | сборка, затем `python tools/run_selftest.py` — самопроверка, шаги по требованиям ТЗ |
| вид прототипа (`app.css`, `body.html`, разметка в `app.js`) | плюс `python tools/kit/check_page.py` и `python tools/check_ui.py` (контраст, выход за край на 360 px, кнопки без подписи; `--shots <scratchpad>` — снимки посмотреть глазами) |

Параметры проверок набора — `.claude/kit.json`, описание — [tools/kit/README.md](tools/kit/README.md). Свои проверки проекта — `tools/*.py`, описание — в начале каждого скрипта: `check_trace.py` — каждый пункт ФТ из `.docx` есть в ТЗ и приложение А согласовано с таблицами; `run_selftest.py` и `check_ui.py` — Playwright для Python. Без Playwright самопроверка — открыть `prototypes/index.html?selftest` в браузере: отчёт в углу страницы, итог — `data-selftest="pass|fail"` у `<html>`. Не прогнал проверку — так и сказать, с причиной.

## Договорённости

- Перед правкой — `git fetch`; есть новое на GitHub — предложить подтянуть.
- Коммит и push — только по просьбе. Коммитов на пункт плана два: исправление (`BUG-01: …` — сообщение начинается с номера пункта) и отметка `[x]` с хэшем в `plan.md` (`Хэш <коммит> в плане ревью <дата>`).
- Пункт из таблицы решений плана — в работу, только когда заполнено «Решение».
- Новое требование в ТЗ — с идентификатором, приоритетом, ссылкой на ФТ (или пометкой «расширение») и строкой в приложении А; новый экран или действие прототипа — со ссылкой на требование.
- Новое поведение прототипа — вместе с шагом самопроверки в `prototypes/src/selftest.js`, шаг называет требование ТЗ и падает до правки.
- Правка ТЗ — версия и дата в шапке, запись в `Specification/CHANGELOG.md`. Идентификаторы требований не переиспользуются; удалённое требование помечается «исключено», а не стирается.
- Язык документов и сообщений коммитов — русский, простыми словами.

## Скиллы

`/lpr-review [роль]` — ревью ТЗ и прототипа; `/lpr-fix <пункт>` — выполнить пункт плана. Общие файлы скиллов и `tools/kit/` приходят из ClaudeKit (`../ClaudeKit`, версия — `.claude/kit.json`): правятся там и переносятся командой `python ../ClaudeKit/apply.py update .`. Своё для проекта — этот файл, чек-лист [.claude/skills/lpr-review/checklist.md](.claude/skills/lpr-review/checklist.md), `.claude/kit.json`, `.claude/evals/triggers.md`.
